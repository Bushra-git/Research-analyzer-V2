# Paperlane folder guide

The application root is `Research-analyzer-V2-main/` inside the downloaded parent folder. Run Docker Compose and Python commands from this application root. Run npm commands inside `frontend/` or `backend/`; there is no root npm application.

```text
Research-analyzer-V2-main/
├── frontend/          React application, public assets, tests and Nginx configuration
│   ├── src/           Interface components, styles and API client
│   ├── public/        Browser assets and manifest
│   ├── build/         Generated production build (preserved)
│   └── node_modules/  Installed frontend dependencies (preserved)
├── backend/           Express API, authentication and ownership checks
│   ├── prisma/        Database schema and migration history
│   ├── tests/         API security tests
│   └── node_modules/  Installed backend dependencies (preserved)
├── datasets/          Venue datasets and sourced publication-fee metadata
├── models/            Local embedding model and revision manifest
├── scripts/           Setup, model download, evaluation and metadata refresh tools
├── tests/             Python tests and retrieval fixtures
├── docs/              Architecture, evaluation evidence and implementation notes
├── .github/           Continuous integration workflows
├── .venv/             Installed Python environment (preserved)
├── .tools/            Local Python runtime, tooling and supporting downloads
├── app.py             Private Flask API
├── analysis_tasks.py  Manuscript analysis pipeline
├── worker.py          RQ worker entry point
├── queue_resources.py Shared Redis and queue configuration
├── *.py               Retrieval, venue, domain and compatibility modules
├── requirements*.txt  Python dependency specifications
├── docker-compose.yml Service definitions
├── Dockerfile         Python service image
├── .env               Local configuration/secrets (preserved; do not publish)
├── .env.example       Configuration template
├── model.pkl          Preserved legacy project artifact; unused by production
├── LICENSE            Project license
└── README.md          Setup and usage instructions
```

## Conservative cleanup — 4 November 2026

Removed only:

- Root, `tests/` and `scripts/` Python `__pycache__` folders: generated bytecode.
- Root `.pytest_cache/`: generated pytest state.
- `.tools/uv.zip`: leftover installation archive; the extracted tooling remains.
- Root `package-lock.json`: empty dependency map with no corresponding root `package.json`. The real frontend and backend lockfiles remain.

This removed 46 files totaling 21,121,131 bytes (approximately 20.14 MiB). SHA-256 comparisons confirmed that all 2,825 files in the protected inventory remained unchanged during deletion. Every deletion target was checked to remain inside this application root, and linked targets were rejected.

No application source was moved or edited. Databases, Docker volumes, running services, secrets, installed dependencies, model weights, datasets, existing documentation, evaluation results and compatibility modules were preserved. Older project assets and the original DOAJ download were also retained rather than assuming they were disposable.

In particular, `.venv/pyvenv.cfg` points to the Python runtime under `.tools/python/`. Deleting `.tools/` would break this environment. Keep the nested application folder name and Python module locations unchanged unless imports, Docker paths and environment paths are deliberately migrated together.

Generated caches may reappear during normal development; their presence does not mean the cleanup failed.
